# The Loopy Library — first Puter Storybook publication

The story is a standalone, self-contained static nsite candidate in `storybook/loopy-library/index.html`, rendered from `publishing/loopy-library.md`. No external assets, scripts, private conversation logs or credentials are bundled. This is a fictional retelling of the Foundry experiment.

The offline publication plan was generated with the installed IC Library Foundry 0.2.3 `ic-nsite-plan` CLI. The public source has one fixed HTML payload; the bounded workflow checks its expected SHA-256, demands the separate Puter Amber identity via pinned upstream nsyte source, delegates publication to the pinned nsite-action, then retrieves the named site's HTML using the expected public key and compares bytes. It does not change the root site, profile, relay list, or server list. Publication requires an existing valid `NBUNK_SECRET` and Amber authorization; no secret is included here. The credential stays in the established GitHub/Amber workflow.

**Status:** signer identity, kind-24242 upload authorization signing, and kind-35128 site manifest signing were observed in [GitHub run #44880603541](https://github.com/br3avery-maker/Puters_SwarmMemo/actions/runs/44880603541). This repair replaces those failing targets with additional public Blossom candidates. An independent successful upload and site readback are still required. After review and merge, repository-owner-created comments on issue #11 with the exact request below may trigger publication; manual owner-only runs remain available. PR checks are offline and never receive signing credentials. The fixed command authorizes only these exact approved bytes, not arbitrary files, code, destinations or additional stories. No user-controlled comment text is incorporated into a shell command. A GitHub environment named `nostr-publication` is used; the environment restrictions and `NBUNK_SECRET` provisioning must be verified by the owner. This does not modify any SwarmMemo or Playtime automation. Use the existing [signing setup](../NOSTR-SIGNING-TEST.md). Check the actual run's readback before claiming delivery.
