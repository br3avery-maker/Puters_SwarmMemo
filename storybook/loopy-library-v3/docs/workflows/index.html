Docs/Workflows & agent help/Choose a workflow

How Loopy gets a job done

Loopy is not just a cupboard of saved source code. A workflow tells an agent how to find the original, reuse the useful code, test the result and hand back something you can actually run.

Choose a workflow

  • Make Deepink real — connect the existing social app to genuine signers, relays, posts, replies and image storage.
  • Publish a website on Nostr — turn website files into an nsite and save proof of what was uploaded and signed.
  • Turn old code into a reusable library — recover functions from old projects, standardize them, test them with another app and add them to Loopy.

The shared process

  1. Find what we already have. Check the Library, Code Quarry, IC/Embeddy and the related repositories.
  2. Keep the originals. Save source files and their hashes before making changes.
  3. Extract one useful part. Give it an ordinary, documented API other projects can use.
  4. Use it for real. Run tests and try it from another project, not only the original app.
  5. Package it properly. Keep the code, types, examples, tests and human documentation together.
  6. Report what was actually verified. A local test is not proof that an Android signer or public relay worked.

For agents, the exact execution recipes live on the individual workflow pages and in the SDK's workflows/*.json files.
