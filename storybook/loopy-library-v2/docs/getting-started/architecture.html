Architecture

The SDK has independent modules and a small optional facade. Imports do not sign, connect, or publish on their own.

@chaoticka/nsite-loopy-sdk
├─ Core       byte tools, URLs, options
├─ Nostr      events, signing, relays, feeds, profiles
├─ Nsite      signed manifests, files, publishing pipeline
├─ Blossom    upload authorizations, exact-byte verification
├─ Archive    ZIP, CAS, version history, searchable catalog
├─ Directory  metadata, collection and clone-stack curation
├─ Storage    memory and IndexedDB
├─ Adapters   browser capability and Android host handoff
└─ Facade     createNsiteSDK / publish / query

Host responsibilities

The browser or Android host owns its UI, connection lifecycle, approved signer and callback wiring. The SDK checks signatures and relay receipts but does not supply a universal Android ActivityResult implementation.

State and privacy

Use a dedicated signing provider for secrets. The generic Storage adapters are for application state and cached content, not private keys. Preserve raw source code and provenance separately from publicly shareable documentation.

Deployment boundaries

Nsite.publishNsite performs a publication workflow only when invoked with a real signer and endpoints. The docs site itself is static and includes no live signing credentials.
