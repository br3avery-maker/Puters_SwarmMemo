Docs/Workflows & agent help/Reuse old code

Turn recovered code into a reusable library

Find the useful parts hiding inside old nsite ZIPs, HTML projects, and repositories, then turn those parts into functions other apps can import. This is the Loopy Library workflow that stops us rebuilding the same signer, relay, and storage machinery for every project.

When to use it: Use this when a project needs something we already built elsewhere, or when recovering code from an older app.

What happens

  1. Find the originals. Scan source projects safely, record filenames and hashes, and identify exact duplicates.
  2. Recover real code. Keep exact source bytes and the original project paths so nothing useful is lost.
  3. Ask Loopy and Embeddy. Search the existing semantic index and Code Quarry for related implementations, rather than trusting filename matches alone.
  4. Make a clean API. Extract one reusable operation with standard inputs, outputs, errors, and dependencies; do not clone the whole old app.
  5. Try it in another app. Run positive and failure tests, and use the module from a fresh consumer project.
  6. Package and explain. Update the library, human documentation, machine-readable contracts, tests, and source history together.

What you get

A tested, importable capability with an API, documentation, examples, and a way to trace it back to its source.

For agents: workflow instructions

A search result or embedding match is only a lead. A capability becomes reusable after extraction and consumer testing.

The structured recipe below is available for automation and integration tools. You do not need to read it to understand the workflow.
