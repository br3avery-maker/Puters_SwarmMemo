Security and trust boundaries

Loopy’s safety rules are about keeping your keys with your signer, checking what servers actually returned and refusing to call unfinished operations successful.

  1. Signer custody. Use user-approved NIP-07, NIP-46, or Android NIP-55 signers. The generic storage adapter must not hold nsec secrets or bunker transport credentials.
  2. Android result validation. External intent launch is not login. Verify callback/correlation, expected author, canonical event ID and BIP-340 signature.
  3. Relay verification. Signed events must verify; relay OK without exact-ID readback is insufficient for durable publication claims.
  4. Blossom integrity. Check signed upload authorization, hash descriptors, and downloaded bytes; never trust a returned URL alone.
  5. Archive safety. Reject ZIP traversal paths, symlinks, invalid CRC, oversized/decompression-bomb entries and duplicate names.
  6. Publication authority. Creating local docs or testing with mock relays does not authorize a public Nostr event or deployment.
  7. Source rights. The SDK is private/reviewable until licenses are cleared for public redistribution. Do not publish the full donor collection unreviewed.

This guide summarizes security contracts declared in the delivered SDK sources and docs; it is not a security audit of a production deployment.
